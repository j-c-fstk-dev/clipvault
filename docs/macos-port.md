# Porting ClipVault to macOS

Status: **in progress.** Stage 1 is done: the code that depends on the
operating system lives in `src-tauri/src/platform/{linux,macos}`, and CI
builds and tests the macOS side on every change. The macOS side does not
capture the clipboard yet.

This page lists what has to be solved, what we know about each part
(researched in October 2026), and the plan.

## What stays the same

The UI (React), the SQLite history, file snapshots, backups, settings,
translations, the tray menu, the global shortcut and notifications are
cross-platform already. Locating moved files by inode (`locate.rs`) also
works on APFS.

## What each platform provides

| `platform::` | Linux | macOS (planned) |
|---|---|---|
| `capture::Watcher` | X11 XFixes events | Poll `NSPasteboard.changeCount` (no change notification exists) |
| `serve::ClipboardHandle` | X11 selection owner, INCR | `NSPasteboard` `clearContents` + `writeObjects` |
| `open` | GIO content types and apps | `NSWorkspace` `URLsForApplicationsToOpenURL`, `UTType` |
| `track::Tracker` | inotify on source folders + inode search | `NSURL` bookmark data, which resolves moves and renames on the same volume |
| `autostart` | `~/.config/autostart/clipvault.desktop` | LaunchAgent in `~/Library/LaunchAgents` (**done**) |
| `window::is_active` | `_NET_ACTIVE_WINDOW` | Not needed (toolkit focus is reliable) |
| `lower_priority` | `ioprio_set` idle + `nice` | Utility QoS class (**done**), which also throttles I/O |

## Findings

### Clipboard privacy (the biggest unknown)

- Since macOS 15.4, `NSPasteboard.accessBehavior` exists. For the general
  pasteboard, programmatic reads default to **asking the user**; once asked,
  the app appears in System Settings (reportedly *Privacy & Security → Paste
  from Other Apps*) with Ask / Always Allow / Always Deny. Paste actions the
  user starts are always allowed. There is no entitlement and no API to
  request access up front.
  <https://developer.apple.com/documentation/appkit/nspasteboard/accessbehavior-swift.enum>
- Through macOS 26 the alert was opt-in (`EnablePasteboardPrivacyDeveloperPreview`);
  the macOS 27.2 release notes say that default was removed. Whether the alert
  is now on for everyone **must be tested on a real Mac**.
- Reading `changeCount` and `types` is not documented as alerting (on iOS such
  metadata reads do not alert). Reading contents (`stringForType`,
  `dataForType`, `readObjects`) does.
- Maccy, the best-known open-source clipboard manager, still polls
  `changeCount` every 0.5 s and reads the items.

**Plan:** check `accessBehavior` at startup; explain the prompt on first run
and recommend *Always Allow*; when it is *Always Deny*, show how to change it
instead of failing silently.

### Reading the clipboard

- Types: `public.utf8-plain-text`, `public.html`, `public.rtf`, `public.png`,
  `public.tiff` (convert to PNG with `NSBitmapImageRep`), `public.file-url`.
  Finder puts one pasteboard item per copied file; read them with
  `readObjectsForClasses:[NSURL] options:{FileURLsOnly}`.
- Some apps put several items on the pasteboard for one copy; merge them into
  one history entry.
- Skip content marked by password managers (nspasteboard.org):
  `org.nspasteboard.ConcealedType`, `org.nspasteboard.TransientType`,
  `org.nspasteboard.AutoGeneratedType`, and legacy markers such as
  `com.agilebits.onepassword`. KeePassXC and the Bitwarden desktop app set
  `ConcealedType`.

### Pasting into the previous app

ClipVault copies the item and hides its window; the user pastes. That needs
no permission. Hiding the app returns focus to the previous app; on macOS 14+
`yieldActivation(to:)` makes that reliable. Auto-paste (sending Cmd+V) would
need the Accessibility permission and is not planned.

### Rust and threads

- Crates: `objc2` 0.6, `objc2-foundation` / `objc2-app-kit` /
  `objc2-uniform-type-identifiers` 0.3, `block2` 0.6.
- Use one dedicated thread for the pasteboard (poll, read, write). Run
  `NSWorkspace` calls that may show UI and all `NSApplication` calls on the
  main thread (`run_on_main_thread`).

### Following moved files

Store `NSURL` bookmark data when a file is copied. It resolves after moves and
renames on the same volume (it keeps the volume and file ID), usually also
after a move to the Trash; refresh it when it reports stale. Moves to another
volume break it, so keep the current inode and name+size search as fallback.

### App bundle and look

- Menu-bar app: hide the Dock icon (`ActivationPolicy::Accessory` or
  `LSUIElement`), tray icon as a template image so it follows the menu bar.
- Native glass: Tauri `windowEffects` with `transparent: true` — `Sidebar`,
  `UnderWindowBackground`, and on macOS 26 `LiquidGlassRegular` /
  `LiquidGlassClear`. `titleBarStyle: "Overlay"` with traffic lights over the
  sidebar.
- Data lives in `~/Library/Application Support/com.jorgecristo.clipvault`.
- The global shortcut uses Carbon hot keys: no permission needed.
- Notifications ask for permission once.
- Set `bundle.macOS.minimumSystemVersion` (proposal: 13.0).

### Building and distributing

- GitHub Actions `macos-latest` (Apple Silicon); a universal build
  (`--target universal-apple-darwin`) also covers Intel Macs. Output: `.app`
  and `.dmg`.
- **Unsigned / ad-hoc signed** (`signingIdentity: "-"`, free): on macOS 15+
  the first launch is blocked; the user opens *System Settings → Privacy &
  Security → Open Anyway* (right-click → Open no longer bypasses it).
  `xattr -cr /Applications/ClipVault.app` also works. Good enough for testers.
- **Signed and notarized** (Apple Developer Program, US$ 99/year): opens with
  no warning. Tauri signs and notarizes from CI with `APPLE_CERTIFICATE`,
  `APPLE_CERTIFICATE_PASSWORD`, `APPLE_ID`, `APPLE_PASSWORD` (app-specific),
  `APPLE_TEAM_ID` as secrets. Needed before selling.

## Plan

1. **Platform layer** ✅ — Linux code under `platform/linux`, macOS
   placeholders, LaunchAgent autostart, CI on `macos-latest`.
2. **Clipboard on macOS** — `changeCount` polling, reading all types,
   password-manager markers, writing back (text + HTML, images, files),
   `accessBehavior` handling and first-run explanation. First build for the
   tester.
3. **Native integration** — open-with list with app icons, bookmarks for
   moved files, menu-bar app (no Dock icon, template icon), native glass and
   overlay title bar, hide settings that only apply to Linux.
4. **Release** — `.dmg` (universal) in the release workflow, ad-hoc signed;
   signing and notarization once there is a developer account.

## Testing on a Mac

Each stage ends with a build for the tester and a checklist: copy text, a
link, an image, several files in Finder; paste each back; check the privacy
prompt; start on login; menu-bar icon in light and dark menu bars.
